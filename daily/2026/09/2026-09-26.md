오늘은 **AFFIX: ZERO의 엔진·아트 방향을 사실상 다시 시작한 날**이었다.

전날 Godot 실플레이에서 확인한 품질 문제를 그대로 덮어두지 않고,
기존 비주얼 자산을 폐기하고 게임 규칙만 보존한 채 새 엔진 기준으로 재출발하는 쪽으로 방향을 바꿨다.

GONY DAILY는 자동 runtime state 갱신만 확인했다.

## 1. AFFIX: ZERO Art Reset

### 진행한 작업

- 기존 이미지 자산 전면 폐기
- 기존 다크 판타지 비주얼 방향 폐기
- 과거 이미지를 이름만 바꿔 재사용하는 방식도 금지
- 밝은 캐주얼 탑다운 RPG 방향으로 아트 기준 재선정
- Tiny Swords CC0 구버전, Ninja Adventure, Kenney UI 계열 등 후보 조사
- 신규 자산은 라이선스 / 해시 / 프레임 / 방향 / Pivot / Impact를 검수한 뒤 반입하도록 기준 설정
- 옛 렌더 테스트는 신규 디자인 검증과 섞이지 않도록 비활성화

### 핵심 판단

전날 확인된 문제는 단순 색상 보정이나 Effect 추가로 해결할 수준이 아니었다.

따라서 잘못된 자산을 계속 보정하는 대신
**기존 이미지와 시각 방향 자체를 폐기하고 다시 시작**하는 쪽이 비용이 적다고 판단했다.

### 관련 PR

- [PR #18 — Art Reset](https://github.com/Dev-Gony/affix-zero/pull/18)

## 2. Godot → Unity 전환

### 결정

게임플레이 규칙은 계승하되
Godot 코드와 기존 비주얼 구현을 그대로 이어가지 않고 **Unity 6 + C# + 2D** 기준으로 새 시작하기로 했다.

### 진행한 작업

- Unity 재시작 브랜치 구성
- CombatHealth / MeleeActor / AttackTimeline 등 최소 전투 구조 작성
- 공격 ID 기반 중복 피해 방지
- 실제 타격 프레임과 피해 적용 시점 연결
- First Encounter 최소 전투 흐름 구성
- Animation Clip별 방향 / Frame 데이터 검증 구조 추가
- Unity Dashboard 기반 환경 / Asset 준비 상태 확인 구조 설계
- 새 Art가 준비되지 않으면 임의 Placeholder를 다시 생성하지 않도록 차단
- 기존 Godot 자료는 현행 코드로 끌고 오지 않고 Text Retrospective만 보존
- 순수 C# Core Test 39개 통과
- 실제 Unity Editor Play / 새 Art / Windows Build는 아직 별도 검증 대상으로 유지

### 핵심 판단

엔진을 바꿨다는 사실 자체보다 더 중요한 원칙은
**이전 실패한 시각 구현을 새 엔진에 그대로 복사하지 않는 것**이었다.

게임 규칙과 회고는 보존하지만,
새 프로젝트는 실제 Animation Asset과 Unity Play 검증을 기준으로 다시 구축한다.

### 관련 PR

- [PR #19 — Unity Restart](https://github.com/Dev-Gony/affix-zero/pull/19)

## 오늘 배운 점

1. **틀린 방향을 오래 보정하는 것보다 기준선을 다시 잡는 편이 빠를 수 있다.**
2. **엔진 전환은 코드 복사가 아니라 검증 기준을 다시 세우는 작업이어야 한다.**
3. **과거 자산을 보존하는 것과 새 제품에 다시 쓰는 것은 다른 문제다.**
4. **새 게임 화면이 준비되지 않았는데 임시 도형으로 완료처럼 보이게 만들면 같은 문제가 반복된다.**
