## 1. Prism — 오늘의 운세

### 진행한 작업

- 매일 오늘의 운세 생성 / 표시 기능 추가
- 첫 화면에 오늘의 운세 진입점 추가
- 결과가 없을 때 요청 시 즉시 생성하는 On-demand 흐름 보완
- 비로그인 사용자도 오늘의 운세를 볼 수 있도록 확장
- Web Push 기반 재방문 흐름 추가
- 교차 분석 카드마다 서로 다른 해석이 나오도록 구분

### 핵심 판단

Prism이 큰 Detailed Reading만 제공하면 사용 빈도가 낮아질 수 있다.

따라서 기존 계산 엔진을 해치지 않으면서
**매일 다시 들어올 수 있는 가벼운 진입점**으로 오늘의 운세를 추가했다.

또 교차 분석 카드가 같은 문장 구조를 반복하면
서로 다른 분석 체계를 합친 의미가 약해지므로 카드별 해석을 분리했다.

## 2. Prism + it's me 통합 분석

두 프로젝트를 합칠 수 있는지 구조를 비교했다.

### 확인한 충돌 지점

- 점수 체계
- Route / CSS
- 계정 / DB
- 저장 데이터
- Push Link

### 판단

기능을 한 번에 섞기보다
**it's me를 자기분석 서비스의 상위 경험으로 두고 Prism 분석 엔진을 단계적으로 연결하는 구조**가 더 안전하다고 봤다.

이날은 분석만 수행했고
파일 수정 / Commit / PR / Deploy / DB 변경은 하지 않았다.

---

## 오늘 배운 점

1. **큰 분석 서비스에도 매일 재방문할 이유가 필요하다.**
2. **기존 계산 엔진을 유지하면서 가벼운 Daily Experience를 별도로 만들 수 있다.**
3. **서비스 통합은 화면을 합치기 전에 Identity / DB / Route / Score Model 충돌부터 확인해야 한다.**
4. **분석만 하는 날에는 실제 수정이 없었다는 사실도 기록해야 한다.**
