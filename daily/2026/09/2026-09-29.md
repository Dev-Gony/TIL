# 2026-09-29 작업일지

## 오늘의 핵심

오늘은 사실상 **Re:Place를 서비스 로드맵에 맞춰 V1 마무리에서 V2 초입까지 밀어붙인 날**이었다.

단순 캠페인 모음 화면을 넘어서
보안·데이터 품질·수집 정책·인증·개인화·내 체험단 관리·달력까지
제품의 운영 기준선을 한 번에 정리했다.

GONY DAILY는 자동 runtime state 갱신만 확인했다.

---

## 1. Re:Place 제품 로드맵 정리

Re:Place의 장기 방향을 V1~V4로 명확하게 나눴다.

- **V1**: 주요 체험단 사이트 통합 조회와 탐색
- **V2**: 체험단별 기록·할 일·달력·작성 마감·협찬금액·제공내역 관리
- **V3**: 블로그 분석 / 지수 조회와 자동 글쓰기·대댓글 도구 상품화 검토
- **V4**: 자체 체험단 플랫폼

오늘 구현은 이 로드맵의 V1 안정화와 V2 첫 기능에 집중했다.

## 10. 포트폴리오 관점 정리

Re:Place를 단순 크롤러 프로젝트가 아니라

**여러 체험단 플랫폼의 캠페인 정보를 수집·정규화하고,
지역·플랫폼·보상 조건으로 탐색한 뒤,
사용자별 일정과 할 일까지 관리하는 서비스**

로 설명할 수 있게 됐다.

블로그 마케팅 직무 지원에서도
실제 체험단 업무 흐름을 이해하고 만든 프로젝트라는 점을 보조 포트폴리오로 활용할 수 있도록 정리했다.

## 오늘 배운 점

1. **제품 로드맵이 있으면 기능 추가 순서가 명확해진다.**
   - Auth → 개인 데이터 → 내 체험단 → Task → Calendar 순서가 자연스럽게 이어졌다.

2. **수집 서비스는 데이터 개수보다 데이터 의미 보존이 중요하다.**
   - 0원, 미제공, 전국, 지역 미확인 같은 상태를 억지로 하나로 합치지 않았다.

3. **공개 데이터와 개인 데이터는 처음부터 권한 경계를 나눠야 한다.**

4. **V1에서 V2로 넘어가는 기준은 기능 수가 아니라 사용자 생활 흐름을 관리하기 시작하는 시점이다.**

5. **제품 UI는 장식보다 정보 계층과 행동 구조가 신뢰도를 만든다.**
