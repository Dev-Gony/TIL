## 1. Prism

### 프로젝트 방향

Prism은 사용자의 생년월일을 바탕으로 사주, 서양 점성술, 수비학 세 체계를 각각 계산하고, 공통점·보완점·차이점을 하나의 흐름으로 보여주는 자기이해 서비스다.

핵심 원칙은 **계산과 LLM 설명을 분리하는 것**이다.

- 사주 / 점성술 / 수비학 값은 결정론적 계산 엔진이 담당
- LLM은 계산된 결과를 설명하고 교차 해석하는 역할만 담당
- 출생시간이나 위치가 없으면 필요한 값을 임의로 추정하지 않음

### Starter 분석과 Prism 전환

초기에는 zzsza/saju-starter-code 구조를 확인했지만 그대로 복제하지 않고, Prism의 제품 요구사항과 아키텍처에 맞게 재설계하는 방향을 선택했다.

Quick Reading과 Detailed Reading을 분리하고, 세 분석 체계를 공통 Trait 구조로 정규화한 뒤 교차 분석하는 구조를 핵심으로 잡았다.

## 3. Gemini 연결 구조 개선

### 진행한 작업

- Gemini 연결을 current Interactions API로 전환
- 개발용 Gemini Probe 추가
- Quick 계산 결과와 Gemini Narrative를 분리
- 계산 결과는 즉시 보여주고 AI 설명은 비동기로 추가
- Gemini 지연이나 실패가 전체 분석 화면을 막지 않도록 Fallback 유지
- 기본 Gemini 모델을 3.5 Flash로 전환

### 핵심 판단

LLM 응답을 기다리느라 계산 결과까지 늦어지는 구조를 버렸다.

**결정론적 분석 결과는 즉시 노출하고, Gemini 설명은 이후 비동기 enrichment로 붙이는 방식**으로 분리했다.

이 구조 덕분에 API 지연이나 무료 티어 제한이 있어도 핵심 결과 화면은 계속 사용할 수 있다.

## 오늘 배운 점

1. **계산과 LLM 설명을 분리하면 서비스가 훨씬 안정적이다.**
   - Gemini가 느리거나 실패해도 사주·점성술·수비학 계산 결과는 보여줄 수 있다.

2. **입력값이 없을 때 추정하지 않는 것도 기능이다.**
   - 출생시간 미상 상태를 별도 흐름으로 구현하면서 결과의 정직성을 유지했다.

3. **저장 기능은 재사용 흐름과 연결될 때 가치가 커진다.**
   - 저장 → 검색 → 다시 분석 → 후속 질문으로 이어지면서 Archive가 실제 제품 기능이 됐다.

4. **UI 방향은 제품의 핵심 가치에 맞춰야 한다.**
   - 캐릭터 중심보다 Editorial Report가 Prism의 교차분석 가치를 전달하기에 더 적합했다.

5. **기능을 빠르게 늘릴수록 마지막 회귀 테스트 비용도 함께 커진다.**
   - 구현 종료 기준을 정하고 계산값 검증과 Production Regression을 일괄 수행해야 한다.
