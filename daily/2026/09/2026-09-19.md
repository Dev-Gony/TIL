## 1. AutoShorts

### 진행한 작업

- Gemini를 기본 AI Provider로 추가하고 OpenAI는 선택형 Provider로 유지
- 구형 Gemini 모델/SDK 경로 수정 및 현재 API 흐름에 맞게 대응
- 블로그 이미지를 실제 쇼츠 영상 소스로 활용하도록 렌더링 개선
- Windows 환경에서 한글 자막 폰트를 자동 감지하도록 수정
- 장면 구성, 자막 배치, 음성 타이밍 등 Shorts 영상 품질 개선
- Typecast를 메인 TTS Provider로 추가
- 같은 문장을 여러 음성으로 미리 들어볼 수 있는 Voice Picker 추가
- 처음에는 추천/하드코딩된 캐릭터 목록을 사용했지만 실제 기대한 음성과 차이가 있어 **Typecast API의 실제 Voice Library를 직접 조회하는 방식으로 변경**

### 오늘의 판단

단순히 TTS API를 연결하는 것만으로는 쇼츠다운 결과가 나오지 않았다.

특히 사용자가 듣기에 자연스럽고 익숙한 쇼츠 음성을 찾는 과정이 중요했기 때문에,
자동 추천만 믿기보다 실제 제공 Voice를 비교해서 선택할 수 있도록 UX 방향을 바꿨다.

## 2. GONY DAILY

### 시작점

기존 Tech News Agent는 뉴스 수집·요약 결과를 Slack으로 전달하는 형태였다.

오늘 작업에서는 여기서 한 단계 더 나아가,
**매일 생성되는 뉴스 자체를 하나의 웹 신문으로 남기는 서비스**로 방향을 확장했다.

### 진행한 작업

- Slack 뉴스에 다음 행동을 제안하는 Action Recommendation 추가
- Slack 반응을 수집해 기사 관련도 판단에 반영하는 Feedback Learning 구현
- 기사 이력을 기반으로 Weekly Trend Radar 추가
- 일일 뉴스 결과를 구조화된 Issue 데이터로 저장
- 정적 웹 신문 생성기 구현
- GitHub Pages 자동 배포 파이프라인 구축
- Slack Digest에서 해당 날짜의 웹 신문으로 이동할 수 있도록 연결
- 첫 Production 발행 과정에서 프롬프트/배포 트리거 문제 수정
- 카드형 UI를 버리고 실제 종이신문에 가까운 Front Page 레이아웃으로 전면 개편
- 서비스명을 **TechNews → GONY DAILY**로 리브랜딩
- 브랜드명, favicon, Slack Digest, README, 메타데이터까지 일관되게 변경
- '1면/실행면'처럼 어색했던 섹션 명칭을 자연스러운 신문형 표현으로 수정

### 오늘의 판단

처음 웹 화면은 일반적인 카드형 뉴스 서비스에 가까웠다.
하지만 이미 '신문'이라는 콘셉트를 선택한 이상 웹 서비스처럼 보이게 만들기보다,
실제로 종이신문을 펼쳤을 때의 정보 밀도와 시각적 구조를 가져가는 편이 차별점이 크다고 판단했다.

또 개인 서비스라는 점을 살려 브랜드명을 **GONY DAILY**로 변경했다.

## 3. Re:Place

### 진행한 작업

- 기존 크롤러의 공통 Campaign Model/Persistence 구조 통합
- source id 기반 Upsert로 중복 캠페인 적재 방지
- 검색 필터와 Pagination 추가
- 지역 / 캠페인 유형 / 마감일 기반 필터링 및 정렬 추가
- 크롤러 실패를 숨기지 않고 명확히 드러내도록 오류 처리 강화
- GitHub Actions에서 6시간마다 캠페인 수집하도록 자동화
- Supabase public read와 crawler write 권한 분리
- Public RLS를 Read-only로 구성
- Revu Token 문제 때문에 전체 수집이 멈추지 않도록 **Revu를 임시 제외하고 나머지 수집기를 계속 운영**
- Re:Place 캠페인 탐색 UI 및 Visual System 전면 개편
- Vercel 빌드 시 public Supabase 환경변수가 없을 때 실패하던 문제 수정

### 오늘의 판단

하나의 외부 서비스 인증 문제가 전체 수집 파이프라인을 막는 구조는 운영에 취약했다.
그래서 Revu는 일단 제외하고 정상적으로 수집 가능한 소스부터 계속 운영하는 방향을 선택했다.

또 기능만 있는 화면보다 실제 경쟁 서비스와 비교 가능한 수준까지 끌어올리기 위해
캠페인 탐색 UX와 시각 체계를 전면적으로 다시 설계했다.

## 오늘 배운 점

1. **API 연동 완료와 사용자 경험 완성은 다르다.**
   - Typecast 연동 자체보다 실제로 원하는 Voice를 고를 수 있는 과정이 더 중요했다.

2. **운영 자동화에서는 부분 실패를 허용하는 구조가 중요하다.**
   - Revu 하나의 인증 문제로 전체 크롤러가 멈추지 않도록 분리했다.

3. **서비스의 콘셉트는 UI 결정에 직접 연결되어야 한다.**
   - GONY DAILY를 '신문'이라고 부르면서 카드형 웹 UI를 유지하는 것은 어색했다.
   - 실제 신문 레이아웃으로 바꾸면서 서비스 정체성이 더 명확해졌다.

4. **포트폴리오는 많이 보여주는 것보다 무엇을 남길지 선택하는 것이 중요하다.**
   - 프로젝트가 아닌 Repository와 깨지는 장식을 제거하고 핵심 프로젝트 중심으로 다시 구성했다.
