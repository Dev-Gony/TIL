# 2026-09-20 작업일지

## 오늘의 핵심

오늘은 세 프로젝트를 크게 밀었다.

- **Algo-Memory**: 단순 코드 필사 도구를 단계형 기억 훈련 서비스로 확장
- **Re:Place**: 캠페인 데이터 품질을 다듬고 수집 플랫폼을 여러 곳으로 확장
- **AutoShorts**: 기술 설정이 보이는 도구형 UI에서 실제 서비스처럼 보이는 생성 경험으로 개선

GONY DAILY는 별도 기능 개발보다 자동 실행에 따른 runtime state 갱신이 확인됐다.

## 1. Algo-Memory

### 진행한 작업

- 코드 해설 기능 추가
  - 템플릿 70개에 story / where / keys 설명 추가
  - 초급 템플릿 31개에 줄별 해설 256줄 추가
  - 문제 상세를 해설 / 복습 일정 / 기록으로 분리
  - 암기 완료 후 세 문장으로 설명하는 자가 점검 단계 추가
- 적응형 훈련 방식 도입
  - 표면 오차와 논리 오차를 구분
  - 이전에 틀린 줄과 주변 문맥만 다시 훈련
  - 같은 문제에서 반복 실패하면 그날 반복을 강제하지 않고 다음 날로 이월
  - 실패 문제의 복습 우선순위를 높이는 방식으로 조정
- 코스 UI 개선
  - 훈련 / 실전 버튼 가시성 강화
  - 오늘 차례 표시와 진행 상태 개선
- 제품 범위를 좁히기 위해 독서 / 인사이트 기능 제거
- 공개 배포용 첫 화면과 예시 데이터 추가
  - 처음 방문한 사람이 실제 데이터가 채워진 상태를 바로 체험할 수 있도록 구성
  - 로컬 저장, 로그인 없음, 서버 전송 없음 등의 특성을 명확하게 표시

  - 기존 사용자는 다시 보지 않도록 진입 마찰 최소화
- SQL 학습 지원 추가
  - SQL 템플릿 35개
  - SQLite 기반 실제 실행 검증
  - Python / SQL 코스는 분리하고 대시보드와 통계는 통합
- **깜지 → 설명 보고 쓰기 → 실전**의 중간 단계를 추가
  - 처음부터 백지 코딩으로 보내지 않고 단서를 단계적으로 줄이는 구조
- README 문구와 배포 설정 정리
- Vercel 정적 배포 설정 및 GitHub Pages 배포 트리거 추가

### 오늘의 판단

처음에는 반복 횟수를 늘리는 쪽으로 갈 수 있었지만,
단순 반복보다 **기억에 필요한 단서를 조금씩 제거하는 구조**가 더 중요하다고 판단했다.

그래서 학습 흐름을 다음처럼 정리했다.

또 독서 / 인사이트처럼 핵심 학습 루프와 직접 연결되지 않는 기능은 과감하게 제거했다.

## 3. AutoShorts

### 진행한 작업

- Streamlit UI를 기능 나열형 화면에서 서비스형 생성 흐름으로 재설계
- Shorts 적합도 기준 음성 TOP 8을 우선 노출

- 한국어 Native Voice를 우선 추천하고 Preview 문장도 한국어로 통일
- 이후 사용자 화면에서는 Provider 세부 정보를 감추고 블로그 URL → 영상 스타일 → 기본 음성 → 생성 흐름으로 더 단순화
- 제품형 Hero / 결과 Preview / 스타일 카드 / 생성 흐름을 강화
- 최신 실제 생성 MP4가 있으면 Hero 영역에서 바로 Preview
- Navbar 잘림 수정
- 영상 스타일 카드를 직접 클릭할 수 있도록 UX 수정
- 생성 영역 Padding / 정렬 개선
- 생성 직후 Hero Preview가 즉시 갱신되도록 수정
- Typecast Backend는 유지하면서 Opening Hook / Scene Pacing / 사진 Motion / Transition / Caption Layout 개선

### 오늘의 판단

사용자에게는 어떤 Provider와 모델을 쓰는지보다

그래서 Backend 선택지는 유지하되,
사용자 화면에서는 기술적인 설정을 최대한 감추고 결과물과 생성 경험을 앞에 두는 방향으로 바꿨다.

## 4. GONY DAILY

오늘 별도의 큰 기능 개발보다는 자동 실행에 따른 runtime state 갱신이 확인됐다.

어제 구축한 자동 발행 파이프라인이 실제 운영 단계로 넘어간 만큼,
이제는 기능 추가보다 며칠간 발행 품질과 실패 여부를 관찰하는 단계다.

---

## 오늘 배운 점

1. **학습 도구는 반복 횟수보다 단서의 양을 조절하는 방식이 중요하다.**
   - Algo-Memory에서 반복을 늘리는 대신 단서를 단계적으로 제거하는 구조를 선택했다.

2. **기능을 빼는 것도 제품 개발이다.**
   - 핵심 루프와 붙지 않는 독서 / 인사이트 기능을 제거하면서 Algo-Memory의 목적이 더 분명해졌다.

3. **크롤러는 구현보다 검증 순서가 중요하다.**
   - Re:Place에서 Probe를 먼저 만들고 구조를 확인한 뒤 Production Collector로 전환했다.

4. **사용자는 기술 스택보다 결과를 본다.**
   - AutoShorts에서 Provider 설정을 전면에 노출하기보다 실제 영상 생성 흐름을 우선했다.
